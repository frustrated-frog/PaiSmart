# 知枢全项目视角面试文档改写设计

## 目标

重写 `docs/career/2026-07-27-interview-20-questions.md`，保持“面试官可能提出的 20 个问题 + 详细参考答案”的模拟面试形式。文档不是项目说明书，也不按功能模块机械罗列能力。

每个答案都以整个知枢系统为上下文，从业务目标、总体架构和端到端链路解释具体问题，再深入到相关模块的实现、数据流、故障边界和工程取舍。回答使用第一人称项目负责人视角，体现从需求分析、架构设计、开发落地到稳定性治理的完整所有权。

## 内容结构

20 道题保持真实面试问法，问题覆盖以下能力，但不使用章节式项目讲解结构：

- 项目定位、核心业务问题和总体架构；
- 文档上传、对象存储、异步解析、切片、向量化与索引；
- 混合召回、RRF、重排、父子分块、证据判断与 Agentic RAG；
- Agent Runtime、查询规划、工具调用、预算控制、循环守卫和恢复；
- MySQL、Redis、Elasticsearch、Kafka、MinIO 的职责边界和一致性；
- JWT、组织标签、文档权限、多租户隔离和日志脱敏；
- 对话持久化、引用证据、模型故障转移、长期记忆与评测；
- 前后端协同、可观测性、性能瓶颈、当前不足和演进方向。

## 单题回答模型

每道题根据问题自然组织多段回答，不套用僵硬模板，但完整覆盖：

1. 这个问题在整个系统中解决什么业务矛盾；
2. 我如何拆解需求并确定设计目标；
3. 相关组件在总体架构中的位置与职责；
4. 请求或数据如何流经前端、后端、中间件与模型服务；
5. 正常路径、异常路径和降级路径如何处理；
6. 为什么选择当前方案，放弃了哪些替代方案；
7. 当前实现边界、生产化风险和下一步演进；
8. 面试官继续追问时可展开的代码或数据细节。

## 叙事边界

- 使用“我设计”“我拆分”“我实现”“我选择”的第一人称表达，呈现端到端建设视角。
- 不把答案写成提交记录复述，也不反复强调“新增了某模块”。
- 不虚构 QPS、准确率、召回率提升等未经实际测量的数据。
- 不声称已经实现代码中不存在的能力；未完成部分明确称为当前边界或演进计划。
- 开源依赖按普通基础组件处理；重点说明项目级架构、业务流程与工程治理如何由本人组织落地。

## 图示设计

只在复杂关系显著受益时使用 Mermaid，并将图嵌入对应问题的答案中。预计包括：

- 全系统分层架构图；
- 文档摄入与索引链路；
- 一次完整 Agentic RAG 问答时序；
- Agent Runtime 状态与恢复流程；
- 多租户权限过滤链路；
- 存储职责与一致性关系；
- 运行轨迹与评测闭环。

图示服务于面试回答，不独立扩展成项目讲解章节。

## 完成标准

- 恰好 20 道编号连续的面试问题；
- 每题均包含多段、可口述且有技术深度的参考答案；
- 答案能够自然关联整个项目，而不是只解释近期新增模块；
- Mermaid 围栏、子图和状态/时序块完整闭合；
- 项目类名、存储职责、运行时行为与代码事实一致；
- 无未完成标记、占位文本或伪造性能数据。
