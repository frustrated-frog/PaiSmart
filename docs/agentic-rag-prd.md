# PaiSmart Agentic RAG 2.0 PRD

## 1. 产品定位

PaiSmart 2.0 是面向团队和企业知识场景的可解释 AI Agent。它不只是“上传文档后聊天”，而是能够理解查询意图、选择检索策略、组合文档与工具证据、在证据不足时主动补充检索，并从人工纠错中持续改进的知识工作系统。

产品必须同时满足三类目标：

- 用户目标：回答准确、引用可查、过程透明、失败可恢复。
- 工程目标：多租户安全、链路可观测、模型可降级、模块可独立评测。
- 求职目标：核心算法和工程取舍可通过代码、指标、消融实验和故障演示证明。

## 2. 核心问题

当前版本存在以下产品和技术缺口：

1. 所有知识问题基本进入同一检索函数，缺少结构化意图、复杂度和歧义判断。
2. 现有 Elasticsearch 查询没有形成真正独立的 BM25 与向量排名。
3. 没有 Multi-query、RRF、可替换 reranker 和证据充分性闭环。
4. 标注为“父子分块”的实现没有保存父块，检索粒度和回答粒度仍然耦合。
5. Agent 运行主要依赖手写 ReAct 循环，无法节点级恢复、重放和评测。
6. 反馈只保存为短期字符串，没有形成带来源的纠错记忆。
7. 前端只能看到生成结果，无法解释检索、重排、降级和恢复过程。
8. 没有稳定的离线评测集，不能证明优化是否真实有效。

## 3. 目标与非目标

### 3.1 本期目标

- 建立结构化查询分析和有界 Agentic Retrieval Loop。
- 实现 BM25、向量独立召回，使用 RRF 融合并支持 reranker。
- 保存完整检索 trace，展示候选从召回到最终上下文的排名变化。
- 建立可恢复 Agent Run、Step、Checkpoint 和事件流。
- 建立可治理的纠错记忆，反馈可以在后续相似任务中被检索使用。
- 提供最小可用离线评测与消融接口。
- 完成聊天页的 Agent 工作流、检索证据和运行状态 UI。

### 3.2 非目标

- 本期不实现无边界的 Swarm 或通用多 Agent 平台。
- 不自行训练基础 Embedding 或 Cross-encoder 模型。
- 不允许 Agent 自动发布生产 Skill 或直接修改系统 Prompt。
- 不为了展示概念默认启用 GraphRAG；只有评测证明多跳关系检索需要时才进入后续版本。
- 不在本期实现完整可视化工作流编辑器。

## 4. 用户角色

### 4.1 普通用户

- 上传和管理个人、组织或公开文档。
- 使用自然语言查询知识。
- 查看引用、页码和 Agent 执行进度。
- 对答案点赞、点踩或提交纠错。
- 查看和删除自己的长期记忆。

### 4.2 组织管理员

- 管理组织知识范围和权限。
- 查看检索、模型和 Agent 运行健康度。
- 查看失败任务和低质量回答。
- 管理组织级记忆和纠错规则。

### 4.3 开发/评测人员

- 创建数据集和实验。
- 比较 BM25、Dense、RRF、Rerank、Multi-query 等配置。
- 查看节点 trace、成本、延迟和失败归因。
- 从历史运行生成回归样本。

## 5. 核心用户旅程

### 5.1 简单知识问答

1. 用户输入明确的单跳问题。
2. 系统识别为 `KNOWLEDGE_QA/SIMPLE`。
3. 保留原始查询，跳过不必要的 Multi-query。
4. BM25 与 Dense 并行召回。
5. RRF 融合并重排。
6. 证据充分时直接生成带引用答案。

验收标准：

- BM25 与 Dense trace 均可查看。
- 最终引用能定位文件、页码和 chunk。
- 任一路不可用时能够降级，不导致整次会话失败。

### 5.2 复杂或多跳问题

1. 系统识别为 `COMPARE` 或 `MULTI_HOP`。
2. 查询改写器输出原始、词法、语义和子问题查询。
3. 多路并行召回并融合。
4. 证据检查器识别未覆盖实体或关系。
5. 在预算内执行最多两轮差异化补充检索。
6. 仍不足时部分回答并明确缺口。

验收标准：

- 补充检索必须记录触发原因。
- 第二轮查询与第一轮有明确差异，并排除已覆盖证据。
- 不允许无限循环或重复同一查询。

### 5.3 歧义澄清

1. 用户问题缺失会改变知识域或执行路径的信息。
2. 系统保存 pending task，状态进入 `WAITING_CLARIFICATION`。
3. 前端展示一个关键澄清问题及候选项。
4. 用户补充后合并槽位并从 checkpoint 恢复。

验收标准：

- 用户的短回复不会被当成新任务。
- 澄清前后属于同一个 run lineage。
- 简单缺省字段不得频繁打断用户。

### 5.4 人工纠错学习

1. 用户对答案点踩并给出具体纠正。
2. 系统保存原问题、原答案、纠错、影响节点和来源 run。
3. 纠错以 `PROPOSED` 状态进入校验流程。
4. 激活后，后续相似任务在规划前召回该纠错。
5. Trace 展示本次使用了哪条纠错记忆。

验收标准：

- 纠错不可跨越用户/组织作用域。
- 用户删除记忆后不可再次被召回。
- 记忆召回失败不得阻塞主对话。

### 5.5 断线和故障恢复

1. 运行过程中浏览器断开或后端节点失败。
2. 已产生的事件和 checkpoint 被持久化。
3. 用户重连后恢复事件和已生成内容。
4. 可重试节点从最近 checkpoint 继续，成功步骤不重复执行。

验收标准：

- 重连后步骤顺序和状态一致。
- 有副作用工具不得因恢复重复执行。
- 运行最终状态明确为 completed、failed、cancelled 或 waiting。

## 6. 功能需求

### FR-01 查询分析

- 输出 intent、complexity、entities、constraints、needRetrieval、needClarification、confidence。
- JSON 解析失败时使用规则兜底。
- 保留用户原始查询，不得只存改写结果。

### FR-02 Multi-query

- 支持 ORIGINAL、LEXICAL、SEMANTIC、DECOMPOSED。
- 简单问题可只返回 ORIGINAL。
- 最大查询数可配置，默认 4。
- 查询变体必须保留实体和限定条件。

### FR-03 混合召回

- BM25 与 Dense 使用独立 ES 请求。
- 所有召回通道使用相同权限过滤。
- 每个结果保存 channel、queryType、rank、rawScore。
- 向量服务失败时允许 BM25 降级。

### FR-04 RRF 与重排

- RRF 默认 rank constant 为 60，可配置。
- 以 `fileMd5 + chunkId` 去重。
- Reranker 通过接口接入，支持 no-op/fallback。
- 保存融合分数、重排分数和排名变化。

### FR-05 上下文与引用

- 支持父子上下文或相邻块扩展。
- 依据 token budget、来源多样性和重复度选择证据。
- 保留文件名、页码、锚点和命中原文。
- 冲突证据必须显式呈现。

### FR-06 Agent Runtime

- 运行状态和预算显式化。
- 每个 step 有类型、状态、输入输出摘要、耗时和错误。
- 支持最大步骤、模型调用、工具调用、检索轮数和时间预算。
- 支持重复动作和无进展检测。

### FR-07 持久化

- MySQL 保存 run、step 和 checkpoint。
- Redis 保存活跃事件流和短期生成内容。
- 运行结束后保留审计记录，按策略清理 checkpoint。

### FR-08 记忆与纠错

- 记忆包含 type、scope、content、confidence、provenance、status、version。
- 支持 proposed、active、quarantined、rejected、deleted。
- 查询前可按用户/组织 scope 检索相关纠错。
- 不将模型生成的未验证断言直接保存为事实。

### FR-09 评测

- 提供 JSONL 数据集格式。
- 至少支持 Recall@K、MRR、nDCG、权限泄漏率。
- 支持按检索 profile 运行消融实验。
- 每次实验记录配置和代码版本。

### FR-10 UI

- 聊天消息展示 Agent 工作流和每步状态。
- 检索步骤展示 query variants、两路候选数、融合和重排摘要。
- 显示降级、补充检索、引用和失败原因。
- 页面刷新或重连后恢复轨迹。
- UI 不展示隐藏思维链，只展示系统可观测事件和简洁决策摘要。

## 7. 非功能需求

### 性能

- 简单问答 P95 检索阶段目标小于 1.5 秒，不包含外部模型异常。
- 并行召回不得使用无界线程池。
- 记忆召回和 reranker 均设置超时并可降级。

### 可用性

- 任一非关键增强模块失败不应导致主对话整体失败。
- 模型、Embedding、Reranker 失败有明确降级路径。
- 所有异步任务具备幂等键或去重机制。

### 安全

- 权限过滤在每条召回路径内部执行。
- 低信任文档、工具输出和记忆不能覆盖系统指令。
- 高风险工具必须经过后端权限校验和人工批准。
- Trace 不记录密钥和完整敏感参数。

### 可观测性

- 每次运行拥有 generationId、conversationId、runId 和 traceId。
- 记录各阶段 P50/P95、候选数、降级次数和 token 使用。
- 失败能归因到 query、retrieval、rerank、tool、model、memory 或 persistence。

## 8. 核心指标

- Intent Macro-F1。
- Recall@5/10/20、MRR@10、nDCG@10。
- Reranker nDCG lift。
- Citation Precision/Recall。
- Faithfulness 和无答案识别率。
- Agent task success、平均步骤、重复动作率。
- P50/P95 延迟、TTFT、token 和成本。
- Checkpoint 恢复成功率。
- Correction reuse rate 和 negative transfer rate。
- 权限泄漏率，必须为 0。

## 9. 发布门禁

- Java 编译和新增单元测试通过。
- 前端目标文件 lint 通过，类型检查不存在新增错误。
- 离线检索黄金集核心指标不低于基线。
- 多租户越权测试全部通过。
- 浏览器验证聊天、重连、轨迹和引用路径。
- 新功能默认配置有明确降级路径。
